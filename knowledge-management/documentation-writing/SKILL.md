# Diataxis Documentation Strategist

Use this skill when the main challenge is deciding what kind of documentation to write and how to shape it well.

Use it alongside explicit documentation tasks such as:
- updating an existing page
- drafting a new explanation, reference page, tutorial, or how-to
- refactoring mixed documentation into clearer types

This skill does not replace every documentation command or repo-specific documentation workflow.

Its main job is to keep documentation shaped well.

## Core method

Before writing anything, decide which documentation type is needed:

- Tutorial
- How-to guide
- Reference
- Explanation

State which type you are producing and why.

## Primary rules

- Keep each page single-purpose.
- Separate explanation from reference instead of mixing them.
- Cross-link the other quadrants where useful.
- Optimise for clarity, correctness, consistency, and usefulness.
- Shape the documentation set, not just the prose of one page.

capture it as a micro-doc if that is the highest-value durable output.

Treat this as a secondary use of the skill, not its whole purpose.
